Arc / x402Agent-paid query accessCORE PRIORITY · PLANNED

GET-only paid access using Circle Gateway nanopayments in USDC on Arc. The seller calls settle() before fulfillment; Circle Gateway verifies, locks, queues and later batches onchain settlement. Only completed counts as locally settled.

Read the payment specification
World ID / IDKitHuman-gated free-tier keyCORE PRIORITY · PLANNED

One active self-service free-tier key per action-scoped nullifier, backed by server verification and transactional key lifecycle controls. This trust moment is separate from Agent Pass.

Read the IDKit specification
World ID / Agent PassFresh approval for one operationTHIRD PRIORITY · PLANNED

An agent proposes an exact operation; the backend pauses it; a human freshly authenticates and separately approves or denies the displayed action. Approval is consumed atomically with execution reservation and does not replace Arc payment.

Read the Agent Pass specification
ENSName inputs for two address routesFOURTH PRIORITY · CONDITIONAL

Deliberately narrow: mainnet forward resolution for /v1/balance and /v1/transactions, resolved before payment and pinned through fulfillment. The resolved address stays fixed through retries so the name cannot silently change the paid request.

Read the ENS specification

One product test guides every integration: does it make the investigation easier to request, safer to authorize, or simpler to verify? If it does not strengthen that workflow, it does not belong in the story.
